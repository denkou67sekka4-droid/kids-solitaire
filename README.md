# 建築・換気口業界 情報収集デスク

建築関連案件および換気口メーカーの新情報を毎日収集し、営業活動・見積業務・製品提案に使える形へ
整理する業務用アプリケーションです。デスクトップ上で完結し、外部サーバーもクラウドも使いません。

- **本体は `kanki_intel.py` 1ファイル**（Python 3.9 以降の標準ライブラリのみで動作、追加インストール不要）
- データは実行ファイルと同じ場所の `data/kanki_intel.sqlite3`（SQLite）に保存されます
- 管理画面は `127.0.0.1`（自分のPC）にのみバインドされ、外部からは接続できません

---

## 1. 設計の前提

このアプリは「AIが情報を作る」道具ではありません。**AIは収集済みの原文を分類・要約するだけ**です。

| | 扱い | 保存先 |
|---|---|---|
| 収集した原文（HTML／テキスト） | **正本**。判断の根拠はこれ | `documents` / `document_versions` |
| ルールベース分類 | 決定論的。同じ入力なら常に同じ結果 | `classifications` |
| AI要約 | **派生データ**。事実として採用しない | `ai_annotations`（別テーブル・別画面） |

実装している原則:

| 原則 | 実装 |
|---|---|
| 正本は収集した原文 | 原文HTML（zlib圧縮）と正規化テキストを版ごとに保存 |
| 情報元URL・取得日時・公開日・原文を保存 | `documents` の必須列。画面の「エビデンス（正本）」で常時表示 |
| AIの推測を事実として保存しない | AI出力は別テーブル。画面上も破線枠で「派生データ」と明示 |
| 同じ情報を重複登録しない | 正規化URLのSHA-256で一意制約。SimHashで近似重複・転載も検出 |
| 前回取得時との差分を残す | 本文ハッシュが変化した時だけ新しい版を作り、unified diff を保存 |
| エビデンスを追跡できない情報は採用しない | URL・原文・取得日時が揃わないものは登録せず監査ログに残す |
| robots.txt・利用規約・アクセス頻度を考慮 | 取得前に必ず robots.txt を確認。Crawl-delay と設定値の大きい方を採用 |
| 会員限定情報や認証回避は行わない | HTTP 401/403 は即座に停止し、そのホストへは再アクセスしない |

## 2. 起動

### Windows
`起動_Windows.bat` をダブルクリックします。

### macOS
`起動_Mac.command` をダブルクリックします。
（初回だけ「開発元を確認できません」と出る場合は、右クリック →「開く」を選んでください）

### Linux / コマンドライン
```bash
python3 kanki_intel.py serve
```

起動すると既定のブラウザで管理画面が開きます。ターミナルに表示されるURLには
アクセストークンが含まれます。**このURLからアクセスしてください**（トークンなしでは403になります）。

停止するのは、起動したウィンドウで `Ctrl+C` です。

## 3. 最初に行う設定（重要）

### 3-1. 連絡先を登録する
「設定」タブで**連絡先**（メールアドレスやURL）を登録してください。
これは収集先サーバーのログに残る User-Agent に記載され、相手が問い合わせできるようにするためのものです。

> HTTPヘッダは ASCII しか扱えないため、日本語部分は自動的に除去されます。
> `営業技術部 info@example.co.jp` と入力した場合、送出されるのは `info@example.co.jp` の部分です。
> メールアドレスやURLを必ず含めてください。

### 3-2. 監視対象（情報源）を登録する
「情報源管理」タブで登録します。初期状態では、優先監視メーカー8社と官公庁・業界団体・専門媒体の
**枠だけ**が登録済みで、**すべて停止状態**です。

**URLは同梱していません。** 公式サイトのURLは変わることがあり、誤ったURLを既定値にすると
誤った情報源を正本として扱う危険があるためです。運用者が公式サイトで確認して登録してください。

情報源が実際に収集されるには、次の3つがすべて必要です:

1. 監視URLが登録されている
2. **URL確認済** にチェック（公式サイトの正しいURLであることを確認した）
3. **利用規約確認済** にチェック（収集が規約に反しない／会員限定領域を含まないことを確認した）

3つが揃わないと「収集を有効にする」はエラーになります。これは仕様です。

登録時に「robots確認」ボタンを押すと、そのURLが robots.txt で許可されているか、
Crawl-delay が何秒かを事前に確認できます。

#### 種別の選び方

| 種別 | 用途 |
|---|---|
| RSS/Atom | フィードが提供されている場合。最も負荷が低く確実です |
| 一覧ページ（リンク追跡） | 「お知らせ」一覧など。一覧自体の差分も監視しつつ、記事リンクを辿ります |
| 単一ページ（差分監視） | 1枚もののページ。ページ全体の変化だけを追います |
| 自動判定 | 取得してみてフィードかHTMLかを判断します |

一覧ページで追跡するリンクは、既定では `news` `topics` `お知らせ` `入札` などの語で絞り込みます。
正確に指定したい場合は「追跡リンクの正規表現」を設定してください。

#### 登録できない情報源
匿名掲示板・出典不明のまとめサイト・個人ブログ・根拠を確認できないSNSは、
正本情報源として登録できません（保存時にエラーになります）。

### 3-3. 自動収集
「設定」タブで**毎日自動収集**を有効にし、実行時刻を指定します。
これはアプリを起動している間だけ動きます。

PCの電源が入っていれば確実に動かしたい場合は、OSのスケジューラから次を呼んでください:

```bash
python3 /path/to/kanki_intel.py collect
```

- Windows: タスクスケジューラで毎日実行
- macOS: `launchd` または `cron`
- Linux: `cron`

## 4. 日常の使い方

### ダッシュボード
指定期間の新規取得・差分更新・未確認件数と、分類別／メーカー別／地域別の内訳、
優先度の高い新着を表示します。

### 案件・記事
キーワード・領域・分類・メーカー・商品分野・地域・期間・確認状態・一次情報の状態で絞り込みます。
行をクリックすると詳細が開きます。

**優先度スコア（0〜100）** は次の合計です。情報源の信頼度が高く、監視メーカーと商品分野に
関係し、優先地域で、重要カテゴリ（廃番・受注停止・価格改定・入札・落札など）に該当し、
公開直後のものほど高くなります。

| 加点要素 | 点数 |
|---|---|
| 情報源ティア | 1:22 / 2:20 / 3:16 / 4:12 / 5:13 / 6:9 |
| 優先監視メーカーに該当 | +18 |
| 監視対象の商品分野に該当 | +10 |
| 優先地域（関東7都県）に該当 | +8（全国は +4） |
| 重要カテゴリに該当 | 1件につき +8（最大 +24） |
| 公開から3日以内 | +8（14日以内は +4） |
| 差分が検出された | +10 |

### 記事詳細で確認できること
- **エビデンス（正本）**: 情報元URL / 情報源とティア / 一次情報判定 / 公開日（原文表記も） /
  初回・最終取得日時 / 最終変更日時 / 本文SHA-256
- **原文（正本）**: 保存された本文。「保存済みの原文HTMLを表示」で取得時のHTMLそのものも確認できます
- **差分履歴**: 版ごとの unified diff と、差分から検出した変化の種類（廃番・価格改定など）
- **ルールベース分類**: どの語に反応して分類したかの一覧
- **AI要約（派生データ）**: 破線枠で明示。後述

「共有リンク」ボタンでその記事を直接開くURLをコピーでき、社内で共有できます。

### 一次情報の判定
| 表示 | 意味 |
|---|---|
| 一次情報 | ティア1〜3（公式サイト／官公庁／業界団体）から直接取得 |
| 二次情報（一次リンクあり） | 専門媒体等だが、本文中に官公庁等の一次情報リンクを検出した |
| **一次情報未確認** | 二次情報で、一次情報を特定できなかった。**発表元の確認が必要です** |

### 出力
CSV（Excel向けBOM付き）／JSON／日報用Markdown を、絞り込み条件そのままで出力できます。

コマンドラインからも実行できます:
```bash
python3 kanki_intel.py export --format csv --days 7 --out weekly.csv
python3 kanki_intel.py export --format md --days 1 --min-score 60
```

## 5. AI要約について

AI要約は**任意機能で、既定では無効**です。有効にしなくてもアプリの全機能が使えます。

### 有効にする
1. 「設定」タブで「AI要約を有効にする」にチェック
2. モデルIDを入力（「一覧取得」ボタンで利用可能なモデルを取得できます）
3. APIキーを設定

APIキーは環境変数 `ANTHROPIC_API_KEY` が最優先です。
設定画面から入力した場合は `data/secrets.json`（パーミッション 600）に保存されます。

### AIに何をさせているか
- 入力は**保存済みの原文だけ**です。Web検索も外部参照もさせていません
- 出力の各要点には、**原文からの逐語引用（quote）を必須**にしています
- 受け取った引用が原文に実在するかを**アプリ側で機械照合**します（全角半角・空白の揺れは吸収）
- 照合に失敗した要約は `未検証` として保存し、画面に赤字で
  「原文に存在しない引用がありました。この要約は事実として採用しないでください」と表示します
- AIが判断できない場合は「原文からは判断できません」と回答するよう指示しています

つまり、AIが原文にない話を作った場合、それは**採用されずに検出される**設計です。

## 6. コマンドライン

```bash
python3 kanki_intel.py serve                 # 管理画面を起動（既定）
python3 kanki_intel.py serve --port 8787     # ポートを指定
python3 kanki_intel.py serve --no-browser    # ブラウザを自動で開かない
python3 kanki_intel.py collect               # 収集を1回実行
python3 kanki_intel.py collect --source demo-maker   # 情報源を1つだけ収集
python3 kanki_intel.py sources               # 情報源の一覧
python3 kanki_intel.py sources --seed        # 初期の監視対象候補を登録
python3 kanki_intel.py export --format csv --days 7
python3 kanki_intel.py selftest              # 外部通信なしの自己診断
```

`selftest` は URL正規化・重複判定・HTML/RSS解析・日付解釈・分類・差分検出・
エビデンス判定・AI引用照合・DB一巡・情報源バリデーションを検証します。
アップデート後や動作が怪しいときに実行してください。

## 7. データの保存場所とバックアップ

```
kanki_intel.py
data/
  kanki_intel.sqlite3     ← 全データ（原文・差分・分類・AI要約・監査ログ）
  kanki_intel.sqlite3-wal
  kanki_intel.sqlite3-shm
  secrets.json            ← APIキー（設定画面から入力した場合のみ）
  export/                 ← コマンドラインでの出力先
```

バックアップはアプリを停止してから `data/` フォルダごとコピーしてください。
保存先を変えたい場合は環境変数 `KANKI_INTEL_HOME` にパスを指定します。

主なテーブル:

| テーブル | 内容 |
|---|---|
| `sources` | 情報源（情報源ID・対象名・メーカー・URL・ティア・確認状態など） |
| `documents` | 正本。原文・URL・取得日時・公開日・ハッシュ・一次情報判定 |
| `document_versions` | 版ごとの原文と unified diff、検出した変化の種類 |
| `classifications` | ルールベース分類の結果と、反応した語の一覧 |
| `ai_annotations` | AI要約（派生データ）と根拠照合の結果 |
| `fetch_logs` | 取得ログ。HTTPステータス・robots判定・バイト数・User-Agent |
| `runs` | 収集実行の単位と集計 |
| `audit_logs` | 監査ログ。誰がいつ何をしたか |

## 8. 収集先に迷惑をかけないための動作

- 取得前に必ず robots.txt を確認し、Disallow のURLは取得しません
- robots.txt を取得できないホストへはアクセスしません（保守的に停止します）
- Crawl-delay と設定値の大きい方を同一ホストへの最小間隔として守ります（既定5秒）
- 1情報源1回あたりの取得ページ数に上限があります（既定12ページ）
- ETag / Last-Modified による条件付きGETを行い、更新がなければ本文を取得しません
- HTTP 429 / 5xx を受けたホストは、その実行内では以降アクセスしません
- HTTP 401 / 403 を受けたホストは、認証が必要とみなして以降アクセスしません
- 連続5回失敗した情報源は自動的に停止し、監査ログに記録します

## 9. 制約と、運用でカバーすべきこと

- **PDFの本文は解析しません。** URLと取得ログだけを証跡として残します。
  PDFが主体の情報源は、内容確認を人が行う運用にしてください
- **JavaScriptで描画されるページは取得できません。** 静的HTMLとRSSが対象です。
  該当する場合はRSSの提供有無を確認するか、監視対象から外してください
- **公開日を取得できない場合があります。** その場合は「不明」と表示され、初回取得日時で代用します。
  日付が業務判断に効く案件は原文で確認してください
- **自動収集はアプリ起動中のみ動きます。** 確実に毎日動かすならOSのスケジューラを併用してください
- **分類はキーワードによるルールベースです。** 語彙にない表現は拾えません。
  取りこぼしに気づいたら `kanki_intel.py` 内の `PROJECT_CATEGORIES` / `MAKER_CATEGORIES` /
  `PRODUCT_TERMS` に語を追加してください（`CLASSIFIER_VERSION` も更新すると履歴が追えます）
- **一次情報の自動判定は補助です。** 「一次情報未確認」が付いたものは必ず発表元を確認してください
