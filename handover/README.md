# 荷物引渡し管理

事務PCでお客様情報を登録してQRコードを発行し、引取り時に倉庫のスマホで読み取って
受領サインをもらうまでを一本で管理するアプリです。

```
 事務PC                          お客様                    倉庫のスマホ
 ─────                          ──────                    ──────────
 お客様情報を入力
   ↓
 引渡票(QR)を発行 ──[FAX / メール]──→ QRを持参 ──→ ①お客様QRを読み取る
   ↓                                                      ↓
 荷物ラベルを印刷                                    ②荷物QRを1箱ずつ読み取る
 → 箱に貼る ──────────────────────────────────→        ↓（全部そろったら）
                                                     ③画面にサインをもらう
                                                          ↓
                                                     引渡し完了・記録
```

QRは2種類あります。

| | どこに | 何のため |
|---|---|---|
| **引渡票QR** | お客様へFAX/メールで送る | 「誰に渡すか」を特定する |
| **荷物ラベルQR** | 箱に貼る（個数ぶん発行） | 「その人の荷物か」を1箱ずつ照合する |

この2つを突き合わせることで、**別のお客様の荷物を渡してしまう事故**と
**同じ荷物を二度渡してしまう事故**の両方を防ぎます。

## インストールは要りません

| どこ | 必要なもの |
|---|---|
| 事務PC | **ブラウザだけ** |
| 倉庫のスマホ | **ブラウザだけ**（アプリの配布・ストア審査なし） |
| サーバ役のPC 1台 | Node.js の実行ファイル（インストーラ不要・管理者権限不要） |

`npm install` も不要です。QRの生成・読み取りライブラリ（どちらもMIT）は同梱してあるので、
**外部から何かを取ってこなくても起動します**（社内ネットワークがnpmを塞いでいても動きます）。

サーバ役は事務PCと兼用で構いません。その1台を起動しておけば、
同じ社内LANにいるスマホ・PCからブラウザで使えます。

### 事務が複数名・複数台の場合

**サーバは1台だけ**動かします。残りのPCは、そのPCのアドレスをブラウザで開くだけです
（インストール作業は不要。ブックマークに入れておけば十分です）。

```
        ┌─ 事務PC ①(サーバ役)  ← ここだけ start.bat を動かす
        │
社内LAN ├─ 事務PC ②〜⑨        http://<①のPC名>:8080  をブラウザで開く
        │
        └─ 倉庫のスマホ         https://<①のPC名>:8443  （カメラを使うため HTTPS）
```

サーバ役のPCを選ぶときの注意です。

- **スリープしないようにしてください。** サーバ役PCが眠ると、他の8台からつながらなくなります。
  ［設定］→［システム］→［電源］→［画面とスリープ］で
  「次の時間が経過後、デバイスをスリープ状態にする」を**［なし］**にします
  （画面が消えるのは問題ありません）。
- 一番長く電源が入っている席のPCを選ぶのが無難です。
- 証明書にはPCのコンピュータ名も入れてあるので、`http://PC名:8080` で開けます。
  社内DHCPでIPが変わってもブックマークが切れません。
- Windowsファイアウォールで初回に確認が出たら、**［プライベートネットワーク］を許可**してください。

> データはサーバ役PCの `data\handover.db` 1ファイルに集まります。
> 他のPCにはデータは残りません。バックアップはこのファイルだけ取れば十分です。

### Windows（事務PCで動かす場合）

1. [nodejs.org](https://nodejs.org/ja/download) から **「Windows Binary (.zip)」** を落とす
   （インストーラ版ではなくzip版。管理者権限は要りません）
2. 展開した中身を `handover\node\` に置く（`handover\node\node.exe` になるように）
3. **`start.bat` をダブルクリック**

黒い画面が出たらサーバが動いています。閉じると止まります。
会社名やポートを変えたいときは `start.bat` を右クリック →［編集］で先頭部分を書き換えてください。

### macOS / Linux

```bash
cd handover
npm start          # または  node --no-warnings src/server.js
```

### 初回起動

管理者アカウントが作られ、パスワードが**一度だけ**画面に表示されます。

```
==============================================================
  初回起動: 管理者アカウントを作成しました
    ユーザー名 : admin
    パスワード : xxxxxxxxxxxx
  ※ この表示は一度きりです。控えてください。
==============================================================
```

あらかじめ決めておくこともできます。

```bash
HANDOVER_ADMIN_PASSWORD='任意のパスワード' \
HANDOVER_ORG_NAME='○○運輸株式会社' \
npm start
```

### 環境変数

| 変数 | 既定値 | 説明 |
|---|---|---|
| `PORT` | `8080` | HTTPのポート |
| `HTTPS_PORT` | `8443` | HTTPSのポート（証明書がある場合のみ） |
| `HANDOVER_DB` | `data/handover.db` | データベースの置き場所 |
| `HANDOVER_ORG_NAME` | `荷物引渡し窓口` | 引渡票・ラベルに刷る差出人名 |
| `HANDOVER_ADMIN_PASSWORD` | （自動生成） | 初回起動時の管理者パスワード |

## スマホのカメラを使うには HTTPS が必要（重要）

ブラウザは `localhost` を除き、**HTTPS でないとカメラを許可しません**。
社内LANの `http://192.168.x.x:8080` では、どのブラウザでもカメラは必ず失敗します。
そのため証明書を作ってから起動してください。**これも追加インストールは不要です。**

**Windows**（PowerShell標準の機能だけで作ります。OpenSSLは要りません）

```
scripts\make-cert.ps1 を右クリック →［PowerShell で実行］
```

**macOS / Linux**

```bash
npm run cert
```

どちらもこのPCのIPアドレスを自動で調べ、証明書に埋め込みます。
作り終えたらサーバを起動しなおすとHTTPSが有効になります。

起動時に表示される `https://<PCのIP>:8443` をスマホのChromeで開きます。
自己署名証明書なので警告が出ますが、［詳細設定］→［...にアクセスする］で進めばカメラが使えます。

毎回の警告が煩わしい場合は `certs/server.cer`（Linux/macOSは `certs/server.crt`）を
スマホに転送し、Androidの［設定］→［セキュリティ］→［暗号化と認証情報］→
［ストレージからインストール］→［CA証明書］でインストールすると警告が消えます。

> `certs/` には秘密鍵が入ります。共有フォルダに置いたりGitに入れたりしないでください
> （`.gitignore` 済み）。

> **証明書を用意しない場合でも運用はできます。**
> カメラが使えないときは画面にその旨が出て、番号の手入力に切り替わります。
> 引渡番号は12文字（チェックディジット付き）なので、入力ミスはその場で弾かれます。

### スマホのホーム画面に置く

Chromeのメニューから［ホーム画面に追加］でアプリのように起動できます（PWA）。
アドレスバーが消えるぶん画面を広く使えます。

## FAXで送るときの注意

引渡票QRは**FAXを通ることを最優先に設計してあります**。

- QRにはお客様情報を入れず、12文字の引渡番号だけを入れています
- そのためQRは常に**バージョン1（21×21マス）**に収まります
- 55mm角で印刷すると1マスが約1.9mm。FAXのファインモード（203×196dpi）でも
  1マスあたり約15ドットあり、潰れません
- 用紙は純黒・純白のみで、網掛けや細い罫線は使っていません

**FAXは［ファインモード］以上で送信してください。** 標準モードは縦解像度が半分（98dpi）で、
読み取り成功率が落ちます。

QRの下には引渡番号を大きく印字してあります。FAXがかすれてQRが読めなくても、
この番号を口頭で伝える／手入力することで照合できます。

> QRに顧客名や住所を入れるとQRのバージョンが上がってマスが細かくなり、
> FAXで読めなくなります。`test/qr.test.js` にこれを守るテストを入れてあります。

### メールで送るとき

引渡票の画面から

- **［PDFで保存］** … 用紙まるごとPDFにして添付
- **［QR画像をダウンロード］** … QRだけをPNGで添付

のどちらでも送れます。

## 荷物ラベル

引渡票を発行すると、**個数ぶんの荷物ラベルが自動で作られます**（3個なら 1/3・2/3・3/3 の3枚）。
［荷物ラベルを印刷］からA4に2枚ずつ印刷して、1箱に1枚ずつ貼ってください。

引取り時は、お客様QRを読んだあとに箱のラベルを1枚ずつ読み取ります。
画面に `2 / 3 箱` のように進み具合が出て、全部そろうまでサイン画面には進めません。

- **別のお客様の荷物を読み取ると**、赤い警告と警告音で止まります（誰の荷物かも表示されます）
- **同じ箱を二度読み取っても**カウントは増えません
- どうしても全部そろわない場合は［一部だけ引き渡す］から理由を入力すれば進めます。
  理由は履歴に残ります

> 個数を変更すると荷物ラベルは**発行しなおし**になります（古い番号は無効になります）。
> 印刷して貼り替えてください。履歴にもその旨が残ります。

## 引き取り者のサイン

荷物の照合が終わると、最後に**実際に引き取りに来た方**へ画面にサインをいただきます。

伝票上のお客様と引き取り者が同じとは限らないため、［お引取りの方］で
**ご本人 / 代理の方**を選べます。

- **ご本人**を選ぶと、お名前欄にお客様名が先に入ります（そのまま進められます）
- **代理の方**に切り替えると**お名前欄が空になり、入力し直しになります**。
  初期値のまま確定して、来ていない人の名前で受領記録が残るのを防ぐためです
- 続けて次のお客様を処理するとき、前の受領者名・続柄・サインは必ずクリアされます

### 記録されるもの

引渡しを確定すると、次が消えない記録として残ります。

- 引き取られた方の氏名・ご本人か代理か
- **画面に書かれた受領サイン（PNG画像）**
- 引渡日時・対応した担当者・使った端末
- どの箱を照合したか
- 引渡し時点の記載内容のSHA-256ハッシュ（あとから内容が書き換えられていないかの確認用）

履歴は追記のみで、発行・照会・編集・取消・引渡しがすべて時系列で残ります。
一覧画面からCSVで書き出せます（ExcelでそのままUTF-8として開けます）。

## テスト

```bash
npm test       # サーバ・QR・引渡番号のテスト（53件・追加のインストール不要）
```

画面まで含めた通しテストにはChromiumが要ります（開発時のみ。運用には不要です）。

```bash
npm install                      # 通しテスト用のPlaywrightを入れる

```

`npm run smoke` は Chromium を起動し、カメラに「本物のQRを写した映像」を流し込んで
発行 → 印刷面 → QR読み取り（2段階）→ サイン → 確定 → 履歴確認までを自動で一周します。
`screenshots/` に各画面の画像が残ります。

```bash

```

## 時間外も使いたい場合

**サーバ役PCの電源が入っていれば、時間外でも同じように使えます。**
ただし「電源が入っている」だけでは足りません。PCは動いているのにアプリだけ止まる経路が3つあります。

| 止まる原因 | 対策 |
|---|---|
| Windows Update が夜中に再起動する | 自動起動を登録する（下記） |
| 担当者がサインアウトする | 自動起動を登録する（下記） |
| スリープに入る | ［設定］→［システム］→［電源］でスリープを［なし］に |

いずれも**お客様が来てから気づく**ことになるので、先に潰しておいてください。

### 自動起動を登録する（初回だけ管理者権限が必要）

```
スタートメニューで「PowerShell」を右クリック →［管理者として実行］
cd <handoverフォルダ>
powershell -ExecutionPolicy Bypass -File scripts\autostart.ps1
```

これで、PCの再起動時・サインアウト時・アプリの異常終了時に自動で立ち上がり直します。
以降 `start.bat` を手で動かす必要はありません。

やめるときは `scripts\autostart.ps1 -Remove` です。

> 管理者権限が使えない場合は、`Win+R` → `shell:startup` で開くフォルダに
> `start.bat` のショートカットを置いてください。再起動には追従できますが、
> サインアウトすると止まります。

### 動いているか確かめる

ブラウザで **`/health`** を開くと、動いていれば「動いています」と出ます。

```
http://<サーバ役のPC名>:8080/health
```

ログイン不要で、顧客情報は一切表示しません。
事務の各PCでブックマークしておき、朝と閉店時に見る運用にしておくと安心です。

### バックアップ

24時間動かすなら、1日1回バックアップを取ってください。

```bash
npm run backup            # data/backup/ に日付つきで保存（既定30世代）
```

稼働中に実行しても、整合の取れた1ファイルが作られます。
タスクスケジューラで毎晩動かしておくとよいです。

> `data\handover.db` を直接コピーするのは避けてください。
> 書き込み途中の状態を掴むと、開けない控えができることがあります。

### それでも残る検討事項

上記でサーバは24時間動きますが、**引渡票の発行は事務の方の作業**です。
時間外に「その場で発行して渡す」運用が要るのかどうかは、業務側の設計の話になります
（例：翌日出荷ぶんを前日のうちに発行しておく、など）。
現状のアプリは、**発行済みの荷物を時間外に引き渡す**ところまでは問題なく扱えます。

## 担当者アカウント

**1つのアカウントを全員で共有せず、人ごとに作ってください。**
引渡票には発行した人の名前が刷り込まれ、引渡しの履歴にも対応した人の名前が残ります。
共有アカウントだと「誰がやったか」が追えなくなります。

管理者でログインすると、メニューに **［担当者の管理］** が出ます。

- **追加** … 表示名（例：田中）とユーザー名（例：tanaka）を入れると、
  パスワードが自動生成されて画面に出ます。**表示はこの一度きり**なので、
  その場でご本人に伝えてください（［コピーする］ボタンがあります）
- **パスワード再発行** … 忘れたときはここから。古いパスワードは即座に使えなくなります
- **無効にする** … 退職・異動のとき。ログイン中の端末もその場で切れます。
  履歴は残るので、過去の記録が消えることはありません
- **管理者にする** … 担当者の追加やパスワード再発行ができるようになります。
  事務の責任者の方など、2名以上にしておくと管理者が不在のとき困りません

> 管理者が0人になる操作（自分自身の無効化・最後の管理者の権限剥奪）は拒否されます。

コマンドから作ることもできます（サーバ役PCで実行）。

```bash
npm run adduser -- tanaka 田中
```
- 社内LANでの利用を想定しています。インターネットに直接公開する場合は、
  リバースプロキシ・正規の証明書・アクセス制限を別途用意してください。
