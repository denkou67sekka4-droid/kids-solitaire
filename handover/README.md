# 荷物引渡し管理

事務PCでお客様情報を登録してQRコードを発行し、引取り時に倉庫のスマホで読み取って
受領サインをもらうまでを一本で管理するアプリです。

```
 事務PC                          お客様                    倉庫のスマホ
 ─────                          ──────                    ──────────
 お客様情報を入力
   ↓
 引渡票(QR)を発行 ──[FAX / メール]──→ QRを持参 ──→ ①お客様QRを読み取る
   ↓                                                      ↓
 荷物ラベルを印刷                                    ②荷物QRを1箱ずつ読み取る
 → 箱に貼る ──────────────────────────────────→        ↓（全部そろったら）
                                                     ③画面にサインをもらう
                                                          ↓
                                                     引渡し完了・記録
```

QRは2種類あります。

| | どこに | 何のため |
|---|---|---|
| **引渡票QR** | お客様へFAX/メールで送る | 「誰に渡すか」を特定する |
| **荷物ラベルQR** | 箱に貼る（個数ぶん発行） | 「その人の荷物か」を1箱ずつ照合する |

この2つを突き合わせることで、**別のお客様の荷物を渡してしまう事故**と
**同じ荷物を二度渡してしまう事故**の両方を防ぎます。

## 動かす

Node.js 22.5 以降が必要です（それ以外に必要なものはありません）。

```bash
cd handover
npm install --omit=dev
npm start
```

> `--omit=dev` を付けると、通しテスト用のPlaywright（ブラウザ本体で数百MB）を
> ダウンロードせずに済みます。実運用にはこちらで十分です。

初回起動時に管理者アカウントが作られ、パスワードが**一度だけ**画面に表示されます。

```
==============================================================
  初回起動: 管理者アカウントを作成しました
    ユーザー名 : admin
    パスワード : xxxxxxxxxxxx
  ※ この表示は一度きりです。控えてください。
==============================================================
```

あらかじめ決めておくこともできます。

```bash
HANDOVER_ADMIN_PASSWORD='任意のパスワード' \
HANDOVER_ORG_NAME='○○運輸株式会社' \
npm start
```

### 環境変数

| 変数 | 既定値 | 説明 |
|---|---|---|
| `PORT` | `8080` | HTTPのポート |
| `HTTPS_PORT` | `8443` | HTTPSのポート（証明書がある場合のみ） |
| `HANDOVER_DB` | `data/handover.db` | データベースの置き場所 |
| `HANDOVER_ORG_NAME` | `荷物引渡し窓口` | 引渡票・ラベルに刷る差出人名 |
| `HANDOVER_ADMIN_PASSWORD` | （自動生成） | 初回起動時の管理者パスワード |

## スマホのカメラを使うには HTTPS が必要（重要）

ブラウザは `localhost` を除き、**HTTPS でないとカメラを許可しません**。
社内LANの `http://192.168.x.x:8080` では、どのブラウザでもカメラは必ず失敗します。
そのため証明書を作ってから起動してください。

```bash
npm run cert     # このPCのIPを自動で調べて証明書に入れます
npm start
```

起動時に表示される `https://<PCのIP>:8443` をスマホのChromeで開きます。
自己署名証明書なので警告が出ますが、［詳細設定］→［...にアクセスする］で進めばカメラが使えます。

毎回の警告が煩わしい場合は `certs/server.crt` をスマホに転送し、
Androidの［設定］→［セキュリティ］→［暗号化と認証情報］→［ストレージからインストール］
→［CA証明書］でインストールすると警告が消えます。

> **証明書を用意しない場合でも運用はできます。**
> カメラが使えないときは画面にその旨が出て、番号の手入力に切り替わります。
> 引渡番号は12文字（チェックディジット付き）なので、入力ミスはその場で弾かれます。

### スマホのホーム画面に置く

Chromeのメニューから［ホーム画面に追加］でアプリのように起動できます（PWA）。
アドレスバーが消えるぶん画面を広く使えます。

## FAXで送るときの注意

引渡票QRは**FAXを通ることを最優先に設計してあります**。

- QRにはお客様情報を入れず、12文字の引渡番号だけを入れています
- そのためQRは常に**バージョン1（21×21マス）**に収まります
- 55mm角で印刷すると1マスが約1.9mm。FAXのファインモード（203×196dpi）でも
  1マスあたり約15ドットあり、潰れません
- 用紙は純黒・純白のみで、網掛けや細い罫線は使っていません

**FAXは［ファインモード］以上で送信してください。** 標準モードは縦解像度が半分（98dpi）で、
読み取り成功率が落ちます。

QRの下には引渡番号を大きく印字してあります。FAXがかすれてQRが読めなくても、
この番号を口頭で伝える／手入力することで照合できます。

> QRに顧客名や住所を入れるとQRのバージョンが上がってマスが細かくなり、
> FAXで読めなくなります。`test/qr.test.js` にこれを守るテストを入れてあります。

### メールで送るとき

引渡票の画面から

- **［PDFで保存］** … 用紙まるごとPDFにして添付
- **［QR画像をダウンロード］** … QRだけをPNGで添付

のどちらでも送れます。

## 荷物ラベル

引渡票を発行すると、**個数ぶんの荷物ラベルが自動で作られます**（3個なら 1/3・2/3・3/3 の3枚）。
［荷物ラベルを印刷］からA4に2枚ずつ印刷して、1箱に1枚ずつ貼ってください。

引取り時は、お客様QRを読んだあとに箱のラベルを1枚ずつ読み取ります。
画面に `2 / 3 箱` のように進み具合が出て、全部そろうまでサイン画面には進めません。

- **別のお客様の荷物を読み取ると**、赤い警告と警告音で止まります（誰の荷物かも表示されます）
- **同じ箱を二度読み取っても**カウントは増えません
- どうしても全部そろわない場合は［一部だけ引き渡す］から理由を入力すれば進めます。
  理由は履歴に残ります

> 個数を変更すると荷物ラベルは**発行しなおし**になります（古い番号は無効になります）。
> 印刷して貼り替えてください。履歴にもその旨が残ります。

## 引き取り者のサイン

荷物の照合が終わると、最後に**実際に引き取りに来た方**へ画面にサインをいただきます。

伝票上のお客様と引き取り者が同じとは限らないため、［お引取りの方］で
**ご本人 / 代理の方**を選べます。

- **ご本人**を選ぶと、お名前欄にお客様名が先に入ります（そのまま進められます）
- **代理の方**に切り替えると**お名前欄が空になり、入力し直しになります**。
  初期値のまま確定して、来ていない人の名前で受領記録が残るのを防ぐためです
- 続けて次のお客様を処理するとき、前の受領者名・続柄・サインは必ずクリアされます

### 記録されるもの

引渡しを確定すると、次が消えない記録として残ります。

- 引き取られた方の氏名・ご本人か代理か
- **画面に書かれた受領サイン（PNG画像）**
- 引渡日時・対応した担当者・使った端末
- どの箱を照合したか
- 引渡し時点の記載内容のSHA-256ハッシュ（あとから内容が書き換えられていないかの確認用）

履歴は追記のみで、発行・照会・編集・取消・引渡しがすべて時系列で残ります。
一覧画面からCSVで書き出せます（ExcelでそのままUTF-8として開けます）。

## テスト

```bash
npm test       # サーバ・QR・引渡番号のテスト（53件・追加のインストール不要）
```

画面まで含めた通しテストにはChromiumが要ります。

```bash
npm install                      # devDependencies も入れる
npx playwright install chromium
npm run smoke
```

`npm run smoke` は Chromium を起動し、カメラに「本物のQRを写した映像」を流し込んで
発行 → 印刷面 → QR読み取り（2段階）→ サイン → 確定 → 履歴確認までを自動で一周します。
`screenshots/` に各画面の画像が残ります。

```bash
npm run smoke -- --headed    # ブラウザを表示して確認する
```

## 構成

```
src/
  server.js    起動・ルーティング・静的配信
  routes.js    API（発行・照会・引渡し確定・CSV）
  db.js        SQLite（スキーマと問い合わせ）
  qr.js        QR生成（SVG / PNG）
  token.js     引渡番号の採番・検証
  http.js      HTTPまわりの小道具
public/
  index.html   メニュー
  issue.html   引渡票の発行（事務PC）
  sheet.html   引渡票（印刷・FAX用）
  labels.html  荷物ラベル（印刷用）
  scan.html    QR読み取り〜サイン（スマホ）
  list.html    一覧・検索・CSV
  detail.html  詳細・履歴・サイン表示
```

データベースは `data/handover.db` の1ファイルだけです。バックアップはこれをコピーしてください
（`.db-wal` と `.db-shm` があれば一緒に）。

## 運用上の注意

- **顧客情報とサイン画像が入ります。** `data/` はGitに含めないでください（`.gitignore` 済み）。
- ログインは1アカウント共有ではなく、担当者ごとに分けることをおすすめします。
  「誰が引き渡したか」が履歴に残るためです。

  ```bash
  npm run adduser -- tanaka 田中
  ```

  パスワードが自動生成され、1度だけ表示されます。
- 社内LANでの利用を想定しています。インターネットに直接公開する場合は、
  リバースプロキシ・正規の証明書・アクセス制限を別途用意してください。
